# Worktrace UI 개선 현황

기준일: 2026-09-14. 운영 배포 전 로컬 구현/검증 상태다.

## 1차: 입력과 판단 오류, 그래프 가림

| 우선순위 | 작업 | 상태 |
| --- | --- | --- |
| P0 | 목표 저장 후 다른 프로젝트의 입력과 저장 도중 추가 편집 보존 | 구현, 브라우저 재현 검증 |
| P0 | 프로젝트별 저장 상태, 미저장 표시, 탭 닫기/새로고침 경고 | 구현. 내부 이동 확인 및 탭 메모리 초안 보존까지 완료 |
| P0 | 같은 HEAD 브랜치명을 대표 이름과 +N으로 묶기 | 구현, 13개 이름과 전체 상태 열기 검증 |
| P0 | 요약 그래프 실제 가용 폭 배치, 라벨 글자 폭 측정, 경로와 라벨 행 분리 | 구현, 320/390/768/1440px 검증 |
| P0 | 상태 기반 임의 10%/50% 제거, 산정 전과 0% 구분, 산정 대상 프로젝트만 평균 | 구현, 공통 formatter 및 값 기반 테스트 |
| P0 | 목표/검증센터의 로딩·실패·빈 상태 및 개별 재시도 | 구현, 503/복구/빈 프로젝트 검증 |
| P0 | 저장된 검토 조회 실패 중 일괄 AI 실행 차단 | 구현. 명시적 개별 검토와 일괄 검토를 구분 |
| P1 일부 | WBS 마일스톤 및 진척 산정 포함 여부 편집 | 기존 API 필드를 연결. 모바일/데스크톱 추가·수정 payload 보존 검증 |
| P1 일부 | 진척 막대와 수치의 행 정렬 | 공통 CSS에서 제목 행과 진척 행을 분리 |

목표 저장은 해당 프로젝트의 PATCH 응답만 반영한다. 모든 프로젝트를 다시 불러와
편집 내용을 초기화하지 않는다. 저장 중 추가 입력도 응답으로 덮어쓰지 않는다.
목표 초안을 브라우저 영구 저장소에 저장하는 기능은 추가하지 않았다.

진척은 서버가 계산한 `progress_basis`와 `progress_percent`를 표시한다.
프론트엔드가 커밋 수나 업무 상태만으로 항목별 완료율을 만들어내지 않는다.
산정 WBS와 전체 활동은 별도 의미로 표시하며, 상단 지표 카드는 늘리지 않는다.

## 2차: 화면별 핵심 업무 우선 배치

| 화면 | 작업과 현재 상태 | 완료 기준 |
| --- | --- | --- |
| 공통 | 구현: 평면 제목 행, 2열 모바일 지표, 현재 화면 native 선택 메뉴 | 첫 업무가 모바일 첫 화면에 표시되고 제목/도구줄이 겹치지 않음 |
| 대시보드 | 구현: 프로젝트 행, 이슈/지연 통합 및 유형 필터, 긴 제목 줄바꿈, 전체 행을 유지하는 높이 제한 | 프로젝트·업무명·상태·기한을 한 번에 읽을 수 있음 |
| 프로젝트 목록 | 구현: 목록 우선, 필요 시 생성, 검색/필터/정렬과 URL 보존, 실패/빈 목록 구분 | 생성 폼을 거치지 않고 기존 프로젝트 선택 가능 |
| 프로젝트 상세 | 부분 완료: 반복 지표는 현황 탭으로 이동. 현황 내부 패널 재배치는 후속 | 다음 처리 업무와 최근 근거가 우선 표시됨 |
| WBS·이슈 | 구현: 목록 기본, 필요 시 추가/수정과 초안 유지, 탭/보기/필터/정렬 URL 보존, 모바일 2열 필드 | 뒤로 이동/재진입 후 작업 맥락 유지 |
| 업무 이력 | 구현: 최신순 타임라인 우선, 검색/유형 필터, 필요 시 입력/편집과 상세 입력 분리, API 응답만 반영 | 기록 조회에 긴 입력 폼을 통과하지 않음 |
| 성과 | 후보/검토/확정 단계, 근거 검색·체크 선택 | 근거를 확인한 후보만 성과로 확정 |
| 경력 자산 | 최신 결과 중심, 이전 버전 선택 | 긴 버전별 편집 폼이 누적되지 않음 |
| 목표·마일스톤 | 구현: 프로젝트 선택·조회 우선, 필요 시 편집, 내부 이동 확인과 메모리 초안 보존 | 프로젝트 전환·경로 이동에서도 입력 유실 방지 |
| 검증센터 | 검토 대기 목록/필터, 중첩 카드 축소, 저장된 검토의 근거 복원 | 불필요한 AI 재생성 없이 저장된 판단 근거 확인 |
| 인사이트 | 분석 대상·실행·결과 우선, 실패 후 이전 결과 구분 | 현재 대상과 결과의 기준 시점을 명확히 확인 |
| 리포트 | 기간 프리셋, 요청 조건과 표시 결과 구분 | 재생성 실패에도 이전 결과를 최신으로 오해하지 않음 |
| 로그인 | 현 배치 유지, 비밀번호 표시와 모바일 키보드/오류 상태 점검 | 입력/오류 안내가 키보드에 가려지지 않음 |

## 3차: 큰 데이터와 운영 검증

- 요약 그래프에서 오래된 병합 이력을 의미 단위로 접고, 현재 HEAD·미병합 경로를 우선하는 추가 요약을 검토한다. 현재는 직선 이력만 접으며 분기/병합 지점을 보존한다.
- 긴 브랜치명, 서로 다른 HEAD 13개, 많은 분기·병합, 누락된 부모 이력을 별도 밀도 시나리오로 검증한다. 동일 HEAD 13개 검증과 동일시하지 않는다.
- 프로젝트 0/1/3/20개, WBS 0/8/100개, 긴 한국어 제목과 느린/실패 응답을 포함하는 전체 화면 회귀를 확장한다.
- 실제 운영 계정과 데이터로 배포 후 읽기/저장/웹훅 흐름을 별도 확인한다. 운영 변경은 별도 승인 범위다.

다음 구현 순서는 성과 후보/확정 및 경력 자산 최신 결과 중심 배치,
검증센터의 저장된 근거 복원, 인사이트/리포트의 요청 조건과 이전 결과 구분이다.
이번 개편은 AI나 DB 산정식을 바꾸지 않는다.

## 검증 근거와 한계

- 그래프: 로컬 main의 실제 96개 커밋과 모의 동일 HEAD 13개를 브라우저 API 응답으로 주입했다. 운영 GitHub/DB를 수정하지 않았다.
- 그래프 주요 지점 20개: 모바일 요약 폭 496px에서 가용 폭 370px로 변경. 13개 동일 HEAD 라벨에서도 그래프 높이 82px, 노드 가림과 가로 스크롤 없음.
- 기존 그래프 조회/프로젝트 전환/실패 후 이전 결과 유지/재시도/연결 없음, 키보드 선택, 요약 전환 중 추가 조회 없음도 확인했다.
- 목표/검증센터는 모의 API로 입력 보존, 503과 빈 상태 구분, 재시도를 검증했다. 운영 DB 저장 성공을 뜻하지 않는다.
- WBS 추가/수정의 마일스톤·산정 여부 보존, 상태별 임의 비율 제거, 대시보드 평균과 막대/수치 정렬을 390/1440px에서 확인했다.
- P1: 대시보드·프로젝트·WBS를 320/390/768/1440px에서 모의 API로 검증했다. 모바일 WBS 첫 업무 위치는 752px에서 582px로 줄었으며 문서 가로 넘침이 없다. 프로젝트 진척 막대의 실제 폭도 검사한다.
- P1: 조회 조건의 새로고침·뒤로 이동 복원, 폼 숨김 후 초안 유지, 생성/수정 503과 재시도, WBS 저장 payload의 마일스톤·산정 여부, 프로젝트 0/1/3/20개와 WBS 0/8/100개를 검증했다.
- P1: 나머지 최상위 5개 화면의 390px 헤더/넘침을 smoke 확인했다. AI 결과나 실제 연결된 저장소의 운영 흐름을 검증한 것은 아니다.
- 프론트엔드 단위·소스 계약 테스트, TypeScript, lint, production build를 실행한다. 소스 패턴 테스트만으로 사용자 흐름이 검증됐다고 간주하지 않는다.
- P1 후속: 목표·업무 이력의 320/390/768/1440px 화면, 프로젝트 선택, 메뉴 이동 취소/허용, 브라우저 뒤로 이동, 저장 실패·재시도·저장 중 추가 편집을 모의 API로 검증했다.
- 업무 로그의 조회 실패/빈 결과 구분, 검색·유형 필터, 숨김/탭 전환 후 편집 재개, PATCH/POST/삭제 및 상세 입력 payload 보존을 검증했다. 로그 초안의 전역 경로 이동 보호와 운영 인증을 사용한 로그아웃은 별도 검증 범위다.
- 목표 초안은 현재 탭의 메모리에만 보관한다. 새로고침/탭 닫기를 승인하거나 브라우저가 강제 종료되면 사라지며, 로그인/서버 저장을 대신하지 않는다.
- 기존 로그인 화면의 `window.location.assign()` lint 경고 1건이 남아 있다. 로그아웃은 이동 전 입력 보호와 응답 확인을 추가하면서 router 기반으로 변경했다.
